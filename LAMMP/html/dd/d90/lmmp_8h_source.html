52 dst ──┐
53 num ──┐ |00000000|00000000|
54 |********|********|
55
56 MSB(x) x的最高有效位，比如最高有效位为1，MSB(x)=1

220/*
221 LMMP 内存分配函数指针类型：
222 1. heap_alloc : 堆内存分配器
223 2. heap_free : 堆内存释放器
224 3. realloc : 堆内存重新分配器
225
226 默认使用 malloc、free、realloc 实现。
227 如果你需要传入自定义的分配器，为了避免重复处理，且由于LMMP内部几乎不直接
228 通过指定的指针来进行内存分配，所以为了避免不必要的错误处理，建议遵循一下的行为：
229 1. 传给free的指针应可以为NULL
230 2. malloc(size)可以假定size>0，若size为0，可以是未定义行为，可以直接中断。
231 3. realloc(p, size)可以假定size>0，若size为0，可以是未定义行为，可以直接中断。
232 4. realloc/malloc(p, size)若内存耗尽，或者无空闲块，可以返回NULL，代表分配失败。
233 */
234
235typedef void* (*lmmp_heap_alloc_fn)(size_t size);
236typedef void (*lmmp_heap_free_fn )(void* ptr);
237typedef void* (*lmmp_realloc_fn )(void* ptr, size_t size);
238
239typedef struct {
240 lmmp_heap_alloc_fn alloc;
241 lmmp_heap_free_fn free;
242 lmmp_realloc_fn realloc;
243} lmmp_heap_allocator_t;

245/**
246 * @brief 设置 LMMP 全局堆内存分配函数
247 * @param heap 新的堆内存分配器，可以为NULL，此时会直接返回，而不进行任何操作。
248 * @warning 由于所有共享内存都采用堆内存分配。因此，传入新的堆分配器将会首先调用
249 * lmmp_global_deinit 函数，释放所有共享内存，以保证老旧的堆资源被释放。
250 * 然后将会自动调用 lmmp_global_init 函数，重新分配所有线程局部内存。
251 * 同时，为保证内存不泄露，将会对堆计数器和栈顶以及缓冲池顶进行检查。
252 * 若此时堆栈分配计数器不为 0，或当前栈帧不在栈底，都会触发lmmp_abort函数，
253 * 并输出相应的错误信息。
254 * @note 堆分配器是线程局部的，因此，创建新线程时，如有需要，请自行设置新的堆分配器。
255 * 同时也请自行保证分配器和释放器相匹配。
256 */
257LMMP_API void lmmp_set_heap_allocator(const lmmp_heap_allocator_t* heap);

269/**
270 * @brief LMMP 全局栈初始化函数（通常不需要手动调用）
271 * @note 初始化默认栈，并分配大小为size的额外内存池。如果已经初始化，
272 * 则会直接返回-1，表示已经初始化（并非错误），且不进行任何其他操作。
273 * lmmp_global_init 函数会自动调用此函数，分配的额外缓冲池大小为 LMMP_POOL_SIZE 的大小
274 * （默认为512kb），无需手动调用。

276 * 设置为你想要的值。同时你也可以禁用缓冲池（即size为0），此时不会分配额外缓冲池。
277 * @return 返回0表示成功初始化，返回-1表示已经初始化（并非错误）。

312/**
313 * @brief LMMP 全局退出函数，内部错误或断言失败时调用，若设置了全局退出函数，则会调用该函数，否则会调用默认的退出函数。
314 * @param msg 退出信息，assert类型的错误信息通常仅包含断言内容，其他类型的错误则因类型不同而不同。
315 * @param func 退出处的函数名
316 * @param line 退出处的行号
317 * @param type 退出类型。有以下几个类型：
318 *
319 * 1. ASSERT_FAILURE （枚举值为1）为lmmp_assert触发的退出，lmmp_assert触发的普通退出几乎不可能发生，
320 * 其通常代表不可能发生的计算错误，可能表明程序执行此处时必须正确的输入错误。比如预期无进位的加法产生了进位。
321 * 此类错误不可接受，会导致计算无法继续进行，导致程序崩溃。
322 *
323 * 2. DEBUG_ASSERT_FAILURE （枚举值为2）为lmmp_debug_assert触发的退出。其通常表明预期之外的错误，
324 * 这通常是调用者的UB，如无UB的情况下触发此错误；也可能是LMMP内部的逻辑错误，开发者期待的输入错误，
325 * 在该逻辑处仅简单考虑了某些情况。如有此类错误，可以报告给开发者。此类型只会在定义了
326 * LMMP_DEBUG_ASSERT_CHECK 宏为 1 的情况下才会触发。
327 *
328 * 3. PARAM_ASSERT_FAILURE （枚举值为3）为参数检查失败导致的退出。其通常表明调用者传入了无效的参数，
329 * 导致函数的行为不符合预期。此类错误不可接受，会导致计算无法继续进行，导致程序崩溃。此类型的错误只有在
330 * 定义了 LMMP_DEBUG_PARAM_ASSERT_CHECK 宏为 1 的情况下才会触发。
331 *
332 * 4. MEMORY_ALLOC_FAILURE （枚举值为4）为内存分配失败退出。在使用堆分配器时，申请内存失败，导致触发此错误。
333 * 此类型错误不受明确的宏调控，Realse模式下，会保留必要的触发场景，部分场景下，在一些检查宏定义时，可能会额外触发此错误。
334 *
335 * 5. MEMORY_FREE_FAILURE （枚举值为5）为内存释放错误。当释放堆内存时可能触发，原因通常为头部信息被损坏，极有可能
336 * 源于传入错误的指针，又或者缓冲区溢出导致此头部损坏。LMMP_DEBUG_MEMORY_CHECK 宏为 1 时，才可能触发。
337 *
338 * 6. OUT_OF_BOUNDS （枚举值为6）为数组越界访问导致的退出。通常表明未按规定使用空间。此类型的错误在堆分配器中，当释放
339 * 堆内存时，检测到数组尾部魔数不匹配，导致此错误。LMMP_DEBUG_MEMORY_CHECK 宏为 1 时，才可能触发。
340 *
341 * 7. MEMORY_LEAK （枚举值为7）为内存泄漏导致的退出。在检查点处，堆内存计数器不为0，或者当前栈帧不在栈底，又或者缓冲池
342 * 定不在缓冲池底，都会触发此错误。触发原因可能为，在调用堆分配器重置函数时，显式检查到此时的堆计数器不为0或者栈帧
343 * 以及缓冲池不为底部。又或者手动调用 lmmp_leak_tracker 宏来进行检查，检查到了相同的情况。需注意，手动调用此宏时，
344 * 请先调用 lmmp_global_deinit 进行全局共享的堆资源的安全释放（因为部分全局共享资源也会被计数）。
345 *
346 * 8. UNEXPECTED_ERROR （枚举值为8）为其他未知错误导致的退出。
347 *
348 * @warning LMMP内部中断都将会调用此函数，如果全局退出函数为NULL，则使用默认的退出函数，会打印出全部错误信息，并调用
349 * abort 函数中断程序。自定义全局退出函数请通过 lmmp_set_abort_fn 函数进行设置。请不要在全局退出函数里做任
350 * 何危险的操作，本库的开发者不对其调用产生的影响做任何保证。
351 */
352LMMP_NORETURN LMMP_API void lmmp_abort(lmmp_error_t type, const char *msg, const char *func, int line);
